## 絶対に守る設計原則

1. **方向（上下・売買）の予測・示唆は出さない**。出すのはボラ・確率・分布・禁止帯のみ
2. すべての統計に **n を併記**、n<30は⚠️、**レジーム3分割**（〜2021/2022-23/2024〜）で安定性確認
3. **ユーザーのMT5（GOLD#）が唯一の真実**。当方データ（Dukascopy/Yahoo）とは乖離がある：
   - 金曜終値の差 実測$0.20 / 週明け初値の差 実測$8 / 薄い時間ほどずれる
   - 価格の線の判定は**三値**（確実=誤差帯±0.1%超過／保留／未達）。帯内で断定しない
   - Yahoo取得はスポット失敗時に**先物GC=Fへ代替**する。先物の価格は線として使わない（ラベル済み）
4. ユーザーの実地観察がシステムと食い違ったら、**システムの測定を先に疑う**（過去10件のバグは全てそれで発見された）

## ユーザーからの最重要フィードバック（2026-08-04）

**「定時プッシュ通知は意思決定に関与しない＝無意味」**。これを受けて全自動配信を停止した。
次にやるなら方向性は「プッシュ→プル」：
1. `/plan` オンデマンド計画チェック（Discordスラッシュコマンド+Cloudflare Workers、検証済み統計で PASS/WARN/VETO）
2. `/now` 今入っていい状態かの信号機（禁止側のみ）
3. **MT5センサー**（ユーザーPCのMT5からPython APIで実データ取得→乖離問題の根治・実測スプレッド・建玉連動。docs/system_design_composite.md の究極形）
4. ユーザーのMT5のH1エクスポート提供待ち（もらえたら窓・ブレイク統計を彼の定規で再計算）

## 過去に踏んだ地雷（再発防止）

- 埋め時間の起点バーが週末の死時間を含み24h判定が汚染 → カレンダー判定(JST月曜=金曜+3日)に変更済み
- Yahoo日足の末尾行は「進行中の当日」→ 前日高安は末尾-1行を使う（修正済み）
- Dukascopy再取得の部分失敗が黙ってデータ末尾を削る → 縮小上書き禁止+鮮度警告導入済み
- GitHub Actionsのcronは最大50分遅れる → 配信時刻は前倒しで設計
- dukascopy-nodeはActionsのIPで429になる → 年別分割+低速+リトライで回避（キャッシュ済み）
